## Concurrent jemalloc initialization

Final Windows integration uncovered a cold-start TSD bootstrap race in the
existing jemalloc 5.3.1 build. A separate program linking only jemalloc reproduced
it with six workers and 64 blocks. Both thread-idle and tcache-flush controls still
hung; serialized initialization from an arbitrary worker passed 1,000 fresh
processes. This evidence is independent of LLM transport or JSON handling.

The backend now completes one documented `mallctl("version")` query through
`call_once` before exposing Global/Heap operations or either independent control
entry. Failed initialization is retryable; the factory reports an exception and
the two noexcept controls report false. Allocation flags, caches and dependency
versions are unchanged. All six public entry modes reproduced RED and each
passed 1,000 fresh processes after repair: 6,000 total. Seven bounded permanent
tests cover cold starts and subsequent thread lifetimes.

Independent probes also verified malformed native responses, retries and mixed
24-thread first use. The guard belongs to the linked UniMemory copy. Applications
calling raw `je_*` or sharing one native DLL across independent wrapper copies
must coordinate their own startup; this is not a process-wide lock for such calls.

## Compatibility and scope

The existing [0.x ABI contract](compatibility.md#version) still requires matching
headers and libraries and rebuilt consumers. This repair does not promise a new
stable ABI or introduce an allocator plugin interface. Use matching source
revisions when comparing historical validation evidence with current code.
No universal performance or market-adoption claim follows from these tests.

The repository now distributes the [main source ZIP](https://github.com/dugan-dev/UniMemory/archive/refs/heads/main.zip)
with one permanent branch and no tags or Releases. Library version 0.0.1 remains
unchanged. Match a source revision to its validation record instead of relying
on the version number alone.

MSVC consumers must use a matching runtime configuration. For a Debug-only SDK
with a toolchain mapping release-like configurations to Release, configure the
consumer with `-DCMAKE_CONFIGURATION_TYPES=Debug`; do not silently mix runtimes.
Private-prefix shared allocator libraries require an explicit installation RPATH
or the distributor's documented loader setup.

Hosted CI and main-branch protection are repository/account operations evaluated
separately from code correctness. Paid account changes, privacy changes and a new
stable version are outside this source repair. Contribution, issue and PR
templates now request reproducible evidence; private vulnerability reporting is
enabled through [the security policy](../SECURITY.md). Existing performance results
remain dated historical evidence. Repair commit `65c4a46` passed the 2026-10-09
[cross-platform builds](https://github.com/dugan-dev/UniMemory/actions/runs/37871859097)
and [release validation](https://github.com/dugan-dev/UniMemory/actions/runs/37871859066),
including macOS, ASan and ThreadSanitizer.
