# Typed storage under C++20

`Memory::allocate_objects<T>(count)` and `Allocator<T>::allocate(count)` must provide element storage for pointer arithmetic before a nontrivial element is constructed. A cast from a reused Stack byte address alone does not establish a new array. This is a language-contract defect; a crash is not required to demonstrate it.

For a positive count, the shared internal helper explicitly calls `detail::TypedStorage::operator new(bytes, alignment, memory)`. That function delegates once to `Memory::allocate()`. C++20 N4861 [intro.object/10–13](https://timsong-cpp.github.io/cppwp/n4861/intro.object#10) makes this invocation an implicit object-creation operation and selects a suitable returned object pointer. This applies to a class allocation function called directly, including when its implementation returns reused storage. No new-expression or element constructor is involved.

All array types are implicit-lifetime types, even when their elements are not. Thus the operation can establish the `T[count]` array while nontrivial element lifetimes wait for explicit construction. See [basic.types/9](https://timsong-cpp.github.io/cppwp/n4861/basic.types#9) and [intro.object/10](https://timsong-cpp.github.io/cppwp/n4861/intro.object#10).

The helper obtains the element pointer using `*static_cast<T(*)[]>(storage)`: the cast preserves the returned array pointer, and the array lvalue decays to a pointer to its first element. This uses an ordinary pointer to an array of unknown bound, not a variable-length array extension. It avoids assuming that an array and its first element are pointer-interconvertible, or laundering an element whose lifetime has not begun. See [expr.static.cast/13](https://timsong-cpp.github.io/cppwp/n4861/expr.static.cast#13), [conv.array](https://timsong-cpp.github.io/cppwp/n4861/conv.array), and [basic.compound/4](https://timsong-cpp.github.io/cppwp/n4861/basic.compound#4).

The allocation function takes `std::align_val_t`, so its alignment obligation is exactly the supplied `alignof(T)` under [basic.stc.dynamic.allocation/3](https://timsong-cpp.github.io/cppwp/n4861/basic.stc.dynamic.allocation#3). A plain size parameter for alignment would impose a stronger fundamental-alignment requirement, invalid for a char array at an odd Stack address.

The helper checks count multiplication before allocating and preserves `alignof(T)`. A zero object count still returns null; a zero adapter count still reserves one pairable byte and never dereferences an array. `create_array()` keeps its reverse cleanup on construction failure. Stack deallocation still retains occupied space until reset or rewind.

`tests/typed_storage_tests.cpp` exercises optimized repeated reset/rewind across incompatible array types and bounds, deleted default constructors, cv-qualified arrays, minimum alignment at an odd address, over-alignment, exact allocation statistics, zero counts, overflow, exhaustion, and throwing-constructor cleanup. The old implementation can also pass these runtime checks. These tests guard observable behavior; the C++20 argument above, rather than a claimed runtime RED or sanitizer result, establishes the lifetime correction.
